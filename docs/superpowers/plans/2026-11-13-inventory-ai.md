# 库存缓存与 AI 推荐实施计划

**目标：** 按 PRD §5.1/5.2 完成库存、不超卖、自动实时刷新及真实 DeepSeek 流式卡片推荐。

## 决策
- MySQL 是库存事实来源，条件 UPDATE 和订单事务防超卖；取消只恢复一次。
- Redis 按日期缓存菜单与余量，短 TTL + 随机抖动 + 回源锁防击穿。
- 缓存双删：写前删除，提交后立即删除并延迟500ms再删除；失败重试和TTL兜底。此方案为最终一致，短暂旧值不影响数据库防超卖。
- 页面每2秒自动获取 Redis 库存快照，切日期/离开页面取消轮询；无需人工刷新。
- DeepSeek 官方模型 deepseek-flash，实际联网流式请求；仅发送菜品、偏好、近7天记录及用户需求，不发送邮箱/地址/密钥。
- 后端排除过敏原/售罄/近期点过的菜品，并校验模型结果，逐张推送英文推荐卡片。
- 本地 key 存放忽略文件 .env.local.properties，权限600，不写进源代码或日志。
